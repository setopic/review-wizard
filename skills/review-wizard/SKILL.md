# review-wizard — ブラウザ・ウィザードでの複数質問

AskUserQuestion のブラウザ版。複数の質問（選択肢・複数選択・自由記述・進捗表示）を
1 回の起動でまとめて提示し、回答結果を機械可読 JSON で受け取る。

## 使い分け

- **このツールを使う**: 質問が 3 問以上ある／選択肢の比較検討が要る（図・表・スクショが
  効く）／設計や裁定をまとめてレビューしてもらう場面。図・表・スクショが判断に効くときは
  質問に `detail` を添える（既定で描画される）。
- **AskUserQuestion を使う**: 1〜2 問の即答で済む確認、またはブラウザ（GUI）が使えない
  環境（CI・ヘッドレス・`open` 不可のリモート等）。ユーザーが別の端末からリモートで操作して
  いて、この機械の画面を見ていないときも、その端末が同じ LAN に無いなら使う。このとき `open` は
  成功するが、開いたページはユーザーに見えず、回答できない。リモートかどうかは、ユーザーが
  そう言ったときに分かる。
- **`--host 0.0.0.0` を付けて使う**: ユーザーが同じ LAN の別の端末（スマートフォン・別の PC）の
  ブラウザで回答したいと言ったとき。手順 3 の「LAN の端末から回答するとき」を参照。

## 手順

### 1. 質問 JSON を一時ファイルに書く

スキーマ:

```json
{
  "title": "全体のタイトル（省略可、既定値「レビュー」）",
  "questions": [
    {
      "question": "質問文（必須）",
      "header": "見出しチップ（省略可）",
      "multiSelect": false,
      "options": [
        { "label": "選択肢A", "description": "補足説明（省略可）", "recommended": true, "preview": "<svg>…</svg> 等の見本（省略可・既定で描画）" },
        { "label": "選択肢B", "description": "補足説明（省略可）" }
      ],
      "detail": "<table>…</table> / <svg>…</svg> 等のリッチ説明（省略可・既定で描画）"
    }
  ]
}
```

- `questions` は 1 件以上、各質問の `options` は 2 件以上必須。
- `multiSelect: true` で複数選択可、既定は単一選択。
- おすすめの選択肢には `"recommended": true`（真偽値。省略可）を付ける。ラベルの横に「推奨」の
  印が出る（`--no-rich` でも出る）。**おすすめは先頭に置いて `recommended: true` を付ける**
  （AskUserQuestion の「(Recommended)」と同じ作法）。並べ替えはしないので、順番は options の
  順のまま。回答 JSON の `selected` は label のままで、「推奨」の文字は入らない。ラベルに
  「(推奨)」と書き足さない。
- 各質問には「その他」自由記述欄が自動で付く（options に含める必要はない）。
- **図版・表で質問の意図を詳しく説明したいとき**は、質問に任意の `detail` を足す。
  `detail` は既定で質問文の下に **信頼 HTML** として描画される（詳しい書き方は後述の
  「detail の書き方（図版スタイルガイド）」を参照）。
  - 表は `<table>`、図は **インライン `<svg>`** で書く。画像は **`data:` URI**（例
    `<img src="data:image/png;base64,...">`）で埋め込む。**外部 URL は使わない**（オフライン維持）。
  - プレーン表示にしたいとき（detail を使わない／検証していない外部文字列が混じる懸念がある
    とき）は `--no-rich` を付けると `detail` は描画されない。
  - 選択肢ごとに小さな見本を付けたいときは、選択肢に任意の `preview`（インライン SVG か HTML の
    文字列）を足す。選択肢のカードの中に描画される（書き方は「preview の書き方」を参照）。
    `--no-rich` のときは `detail` と同じく描画されない。
  - `detail` は自分（エージェント）が生成する信頼できる内容に限る。図は自分で SVG を書くか、
    生成した図を data: URI 画像として埋め込む（Mermaid 等のランタイム依存は持ち込まない）。

### 2. バックグラウンドで実行する

回答が送信されるまでプロセスは終了しないため、バックグラウンドで実行し完了を待つ。

```bash
node "${CLAUDE_PLUGIN_ROOT}/scripts/review_wizard.ts" \
  --questions <in.json> --out <out.json> --timeout 1800
```

### 3. ブラウザが自動的に開く

標準出力に印字される `review_wizard: <URL>` の URL がブラウザで自動的に開かれる
（`--no-open` 指定時は開かず、URL を手動で開く運用に切り替わる）。

#### LAN の端末から回答するとき

ユーザーが同じ LAN の別の端末から回答したいときは、手順 2 のコマンドに `--host 0.0.0.0` を
足す。標準出力に `review_wizard: <この機械の URL>` に続けて `review_wizard(LAN): <URL>` が
出るので、`review_wizard(LAN):` の URL をユーザーに伝える（複数行あれば全部伝え、端末と同じ
ネットワークのものを開いてもらう）。トークンが URL に入っているので、URL はそのまま伝える。

- 回答の受け付けは1回だけで、`--timeout` で閉じる。LAN に開くときは `--timeout 0` を使わない。
- 通信は暗号化されない。ユーザーが信頼できる LAN（自宅など）にいるときだけ使う。
- 端末から開けない（読み込みが終わらない）ときは、Windows のファイアウォールが止めている
  ことが多い。`${CLAUDE_PLUGIN_ROOT}/README.md` の「Windows のファイアウォール」の手順をユーザーに伝える。
- ユーザーが言わない限り `--host` は付けない（既定の 127.0.0.1 のままにする）。

#### 自動起動に失敗したとき

自動起動に失敗すると、標準エラーに「ブラウザの自動起動に失敗しました。手動で開いてください」と
URL が出る。サーバはそのまま回答を待ち続けるので、この URL をユーザーに伝えて開いてもらう。

### 4. プロセス終了後に回答 JSON を読む

プロセスの終了コードで結果を判別する。

| 終了コード | 意味 |
|---|---|
| 0 | 回答受領（`--out` のパスに回答 JSON が書かれる） |
| 1 | 入力エラー（質問 JSON 不正など） |
| 2 | タイムアウト（`--timeout` 秒、無回答）、またはサーバの起動失敗。どちらかは標準エラーの内容で見分ける |
| 130 | SIGINT による中断 |

回答 JSON のスキーマ:

```json
{
  "title": "質問JSONのtitle",
  "answeredAt": "ISO 8601 タイムスタンプ",
  "answers": [
    {
      "question": "質問文",
      "header": "見出し（未指定なら空文字）",
      "selected": ["選ばれたoptionsのlabel", "..."],
      "other": "自由記述テキスト、なければ null"
    }
  ]
}
```

`answers` は質問と同じ順序・同じ件数で並ぶ。

## 質問の書き方の型

読む量を減らすため、質問は次の型で書く。

- **問い（`question`）は短く1文**にする。例: 「保存ボタンはどこに置く？」。質問文を長くしない。
- **状況の説明は2〜3行、論点は2〜3個の箇条書き**にする。質問文には入れず、`detail` の先頭に
  短く書く。
- **選択肢の `description` は1行**にする。違いが見た目で伝わるものは、文章で説明せず `preview` を使う。
- **判断の根拠（数値・実例）は `detail` の図や表**にする。根拠の図のための新しい欄は無く、
  `detail` がその置き場になる。`detail` がある質問は、広い画面（幅 960px 以上）では
  問い・選択肢を左、`detail` を右の列に並べて出す。狭い画面では、問いの下・選択肢の前に出す。
  `detail` が無い質問の見た目は変わらない（`--no-rich` のときも同じ）。

見本は `${CLAUDE_PLUGIN_ROOT}/examples/rich-demo.json` の1問目である。

## detail の書き方（図版スタイルガイド）

選択肢の比較検討に効く質問には、原則 `detail` を付ける。文字の説明より図と表を優先する。

- **構成図・フロー図**: インライン SVG で描く。次のスタイルを既定とする。
  - ノードは角丸 `rect`（`rx="10"`）＋ `linearGradient` 塗り＋ `feDropShadow` フィルタ、
    ラベルは白の太字。
  - 矢印は `stroke-width="3"` と `marker-end`、依存や縮小予定の経路は破線
    （`stroke-dasharray`）で描く。
  - 推奨グラデーション: 青紫 `#4F8EF7` → `#7B5BE6` / 青緑 `#22C1A3` → `#19A0DE` /
    橙赤 `#FF8A5C` → `#F5576C`。
- **スケジュール・段階計画**: ガントチャート風の横棒 SVG（グラデーション棒 `rx="8"`、
  縦のグリッド線と期ラベル）で描く。
- **数値・性質の比較**: `<table>`（`thead`+`tbody`）で書く。表のスタイルはウィザードの
  テーマ側が当てるので素の HTML でよい。
- **サイズと自己完結**: SVG の幅は 640px を上限目安にする（カード幅に収まる）。外部 URL は
  使わず、画像は `data:` URI で埋め込む（オフライン維持）。
- **書式**: `detail` は JSON 文字列なので改行を含めず 1 行に畳む。信頼できる自作 HTML のみを
  入れ、未検証の外部文字列を混ぜない。

参考実装として `${CLAUDE_PLUGIN_ROOT}/examples/rich-demo.json` の1問目がこのスタイルの見本である。

## preview の書き方（選択肢ごとの見本）

選択した後の姿を、文字を読まずに見比べさせたいときは、選択肢に `preview` を付ける。

- **幅**: 280px 程度を目安にした小さな図にする（カードの幅に収まるよう `max-width:100%` が
  当たる）。比べやすいよう、選択肢どうしで同じ大きさ・同じ描き方に揃える。
- **中身**: インライン `<svg>` か短い HTML。外部 URL は使わず、画像は `data:` URI で埋め込む。
- **書式**: `detail` と同じく 1 行に畳み、自分が生成した信頼できる内容に限る。
- `preview` を付けない選択肢や質問は、これまでと同じ表示になる。回答 JSON の形も変わらない。

参考実装として `${CLAUDE_PLUGIN_ROOT}/examples/rich-demo.json` の2問目（切り出し順）が見本である。
